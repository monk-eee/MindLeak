- **A reclaimed worktree whose directory still exists silently resolves both planes to a fresh, empty, workspace-local database — the `MissingWorkspace` guard only covers the directory being *gone*.** Observed first-hand this session. A worktree (`MindLeak.worktrees/mindleak-session-management-setup-0b318b93`) was reclaimed by this repository's own automation while a session was live in it. The reclaim removed the tracked files and the `.git` link but left the *directory itself* in place. The `lodestar-mcp` / `mindleak-mcp` processes then restarted (storage is resolved exactly once, at `crates/lodestar-mcp/src/main.rs` line 121 / the matching call in `crates/mindleak-mcp/src/main.rs`, and snapshotted into `storage_status`), re-resolved against that path, and reported `{"origin":"workspace","repository_id":null,"database_path":"...\\mindleak-session-management-setup-0b318b93\\.lodestar/spec.db"}` on both planes. `lodestar_stats` went from 36 active goals / 944 done tasks / 885 knowledge entries to **all zeros**, and `open_session` began returning `get_started` with `reason":"no_active_goals"` — actively inviting the agent to `constitution_define` a first goal into a scratch database it believes is the fleet's authoritative Intent Plane. No error, no warning, no exit code anywhere.
  - **Where.** `mindleak_storage::repository::resolve` — `ensure_workspace_exists` (`crates/mindleak-storage/src/repository/resolve.rs`) and its regression test `a_workspace_that_no_longer_exists_is_refused_rather_than_silently_emptied` (`crates/mindleak-storage/src/repository/mod.rs`). The guard added by `fix(storage): refuse a workspace path that no longer exists` (commit `16179206`) tests `workspace.is_dir()`. A reclaimed-but-still-present directory passes that check, `git rev-parse --git-common-dir` then fails with a non-zero status, `git_common_dir` maps that to `Ok(None)`, and `workspace_database_resolution` fabricates the empty store. The guard's own doc comment claims to defend "a reclaimed worktree"; it defends only the subset where the directory vanishes too.
  - **Impact.** This is the failure mode the guard exists to prevent, and it is worse than a crash: the agent keeps working, fully convinced it is coordinated. Every subsequent `task_claim`, `task_create`, `record_knowledge`, and `task_transition` would write to a throwaway database, so the work is invisible to the fleet and the task it "claimed" stays open for another agent to take — the exact collision Lodestar exists to arbitrate. It also silently defeats `advise`: with no constitution in the scratch database every call returns `needs_human` / `no_constitution_adopted`, which reads as ordinary repository bootstrap state rather than as a broken binding.
  - **Not recoverable in-process.** Restoring a real worktree at the same path (verified: `git worktree repair`, `git rev-parse --git-common-dir` correct again, tree clean at the right HEAD) does **not** recover the running servers, because resolution happens once at startup and is snapshotted. Only a restart of the MCP server processes recovers it, which an agent cannot do from inside its own session.
  - **Why this is not fixed here.** A reclaimed-and-emptied directory is genuinely indistinguishable from a legitimate empty scratch directory by inspecting the directory alone, and `docs`/`SKILL.md` deliberately support the non-Git scratch case ("Outside Git, scratch use stays workspace-local"). So the real fix is a decision, not a patch: either the workspace-local fallback becomes explicitly opt-in (an env var or flag) because the cost asymmetry is enormous — one variable for genuine scratch use, versus silently unjoining the fleet — or the servers re-resolve and refuse on a repository→workspace downgrade rather than snapshotting once. Both change documented behaviour and warrant an ADR. Filed rather than guessed at.
  - **PORTABLE:** a fallback that substitutes a fresh empty store for an authoritative one converts a missing-resource error into silent data divergence. When the fallback and the fault are indistinguishable at the point of detection, the safe default is to make the *fallback* opt-in, not the refusal — the caller who genuinely wants scratch state can say so, and the caller who has lost their real store cannot say anything at all.
