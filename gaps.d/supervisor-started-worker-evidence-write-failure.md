- **A spawned worker is tracked as active only after fallible evidence writes.** In [WorkerRuntime::assign](../crates/ackplane-supervisor/src/daemon/runtime.rs), `adapter.start` can succeed before `queue_use` or `queue_lifecycle` fails, but `active` is assigned only after both writes. Fatal cleanup then sees a confirmed lease with no active worker: `finish` skips explicit termination and can release that lease before the adapter's drop stops the child. This can leave an executing process briefly without its lease and omit terminal evidence. Observed by control-flow inspection during failed-slot delivery cleanup; left for follow-up. Track a confirmed spawn before fallible enqueue operations and add an injected outbox-write regression that verifies process termination before lease release, with recovery evidence retained.
