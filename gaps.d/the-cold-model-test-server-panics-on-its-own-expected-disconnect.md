- **The cold-model test server panics on the disconnect its own scenario is designed to provoke.** `cold_then_warm_json_endpoint` stalls the first request so the client hits its read timeout and retries; the client timing out therefore *closes the connection* — that is the behaviour under test. But the server thread then calls `stream.write_all(headers).expect("write test model headers")` (`crates/mindleak-model/src/test_support.rs:153`), so a write to the now-closed socket panics the thread instead of being ignored. Observed 2026-08-27: `lodestar-core llm::tests::cold_model_read_timeout_retries_once_and_uses_the_warm_response` failed in a full `cargo test -p lodestar-core -p lodestar-mcp` run that took 52.9s under machine load, and passed 3/3 in isolation at ~1.0s each. Impact: an intermittent CI failure whose message points at the test harness writing headers, nowhere near the timing race that caused it — the expensive kind to diagnose, and the kind that trains people to re-run rather than look. The sibling `cold_model_body_timeout_retries_once_and_uses_the_warm_response` shares the shape. Likely fix: on the deliberately-stalled first connection, tolerate a failed write/flush rather than `expect`, since a vanished client is the success condition there. Not fixed this run; found while verifying an unrelated `knowledge_embeddings` change.
