- **The durable supervisor outbox is never actually used to resend anything: `Reconciliation::Resend`'s fields are computed and discarded, and `SupervisorOutbox::enqueue`/`pending` are never called outside tests.** `crates/ackplane-supervisor/src/daemon.rs`'s `serve_once` opens the outbox, reads its `positions()`, and calls `reconcile(positions, connection.accepted_position())` to decide how to treat a fresh connection (ADR-0116 decision 7) -- but the match arm for `Reconciliation::Resend { resend_from, through }` does nothing with either field (`Reconciliation::UpToDate { .. } | Reconciliation::Resend { .. } => {}`), and nothing anywhere in `crates/ackplane-supervisor/src` calls `SupervisorOutbox::pending()` or `SupervisorOutbox::enqueue()` outside `#[cfg(test)]` code (confirmed by grep). Every outbound frame the daemon actually sends today -- registration, session announcement, heartbeat, directive receipt -- goes straight over the live connection via `NodeSyncConnection::exchange_supervisor_frame`, never through the outbox first.
- **Currently harmless in this exact build, because nothing ever enqueues anything.** Since `outbox.enqueue()` is never called, `positions().last_enqueued` is always 0, so `reconcile()` can only ever return `UpToDate` (both sides at 0) or `IncompleteEvidence` (server ahead of a permanently-empty local record) in practice -- the `Resend` arm is reachable in the type system and covered by `reconcile.rs`'s own unit tests plus a direct, outbox-only integration test (`ackplane-bridge/tests/supervisor_reconnect_end_to_end.rs`'s `a_reconnect_declares_its_durable_position_and_resumes_cleanly`, which calls `outbox.enqueue`/`outbox.pending` by hand rather than through the daemon), but never through `serve_once` itself with this daemon's current Notify-only capability set. So no frame is silently lost today; the outbox's whole purpose is simply unconnected to the one thing meant to use it.
- **What remains open, deliberately not attempted here:** deciding which outbound frames should route through the durable outbox at all is a design question, not a patch. Registration/session/heartbeat are already idempotent, re-sent fresh on every `serve_once` call regardless of position, and arguably do not need durable resend semantics; a directive receipt is the one category ADR-0116's own reasoning (`reconcile.rs`'s module doc: "an outbox is for" queued-while-disconnected frames) suggests should be durable, so that a receipt computed by `SupervisorInbox::receive` and lost to a connection drop before `submit_directive_receipt` completes is retried on reconnect rather than silently never resubmitted. Wiring that in touches `serve_once`'s control flow non-trivially (enqueue before send, an actual resend loop reading `outbox.pending()` after a `Resend` reconciliation, sequence numbering shared between the receipt path and the outbox) and needs someone to decide the shape before a worker-driven capability (which will generate real outbound events) is added -- not something to retrofit unreviewed onto a Notify-only build as a side effect of a different fix.
