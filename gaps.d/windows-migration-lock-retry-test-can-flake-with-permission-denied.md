- **Windows migration-lock retry can fail with `PermissionDenied` during a concurrent release -- OBSERVED 2026-08-26, OPEN.** The workspace-wide `cargo test --all` run failed `mindleak-storage`'s `repository::tests::migration_lock_retries_until_a_concurrent_holder_releases_it` at `acquire_migration_lock(...).unwrap()` with `Access is denied. (os error 5)`. The isolated test immediately passed, so the result is timing-sensitive rather than a deterministic assertion failure. `acquire_migration_lock` retries only `AlreadyExists`; on Windows, the create-new attempt racing a lock-file deletion can instead see `PermissionDenied` and exits immediately. Impact: CI can fail spuriously, and a real legacy-migration contender can report an I/O failure instead of waiting for the releasing holder.
