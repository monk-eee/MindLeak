- **A refused call is counted as a failed call, so a working guard reads as a broken tool.** `telemetry_snapshot` reports `reset_database` at a 100% failure rate, but every one of those "failures" is the tool correctly refusing an unconfirmed destructive request — the recorded error is `memory reset requires exact confirmation token: RESET MINDLEAK`. Observed in `crates/mindleak-core/src/facade/observability.rs` (`record_tool_call`), which has no notion of a refusal distinct from an error, so a deliberate, load-bearing safety check is indistinguishable from a defect in the metric. Impact: the health signal is unusable for exactly the tools that guard hardest — a genuine regression in `reset_database` could never move the number, because it already reads 100%, and an operator scanning for the worst-performing tool is sent to the one behaving best. This is the same shape as the projection-freshness defect fixed in PR #781: a gauge that can never read green tells you nothing when it is red. Not fixed this run; found while assessing plane health for an unrelated task.
