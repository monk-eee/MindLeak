# ADR-0056: The changelog is assembled, not edited

- Status: Accepted
- Date: 2026-07-28
- Related: [ADR-0038](0038-isolated-worktrees-shared-repository-state.md)
  (isolated worktrees, shared repository state),
  [ADR-0049](0049-publication-requires-a-claim.md) (publication requires a
  claim)

## Context

Five pull requests in one day reported `CONFLICTING` on GitHub while merging
with zero conflicts in a checkout: #61, #63, #64, #65 and #66. In every case the
only file both sides touched was `CHANGELOG.md`.

`.gitattributes` declares `merge=union` for it, with a comment explaining
exactly why: entries are only ever appended under `## [Unreleased]`, so the
resolution is always "keep both". That reasoning is correct, and git honours it.

**GitHub does not.** Its merge machinery — the merge button, and
`gh pr update-branch` — does not apply `.gitattributes` merge drivers. So the
driver works in every checkout and in none of the places that actually gate a
pull request. `gh pr update-branch` cannot fix it either, because that is a
server-side merge and hits the same wall.

The cost is not the conflict. It is that **auto-merge stops working**. A pull
request is armed, something else lands, and it silently goes stale — it now
needs a human to merge main locally, disarm auto-merge, push, and re-arm. For a
fleet of agents whose whole coordination model assumes armed work lands
unattended, a shared file that every branch appends to is a serialisation point
disguised as a text file.

This is not a new shape. ADR numbers collided the same way and were fixed by a
guard; the ADR index table collided the same way and was fixed by generating it.
`scripts/adr-index.mjs` states the principle in its own header: *"the same
shared-counter shape as ADR numbers, and the same fix: stop hand-maintaining
what can be computed."* The changelog is the last hand-maintained shared
counter in the repository.

## Decision

**A change describes itself in its own file; the changelog is assembled from
those files at release.**

1. **A pull request adds `changelog.d/<section>-<slug>.md`** and does not touch
   `CHANGELOG.md`. The section prefix is one of the Keep a Changelog headings —
   `added`, `changed`, `deprecated`, `removed`, `fixed`, `security` — and the
   file contains the entry exactly as it should appear, as one or more `- `
   bullets. Two branches never write the same path, so there is nothing to
   merge, on GitHub or anywhere else.
2. **`node scripts/changelog.mjs --release <version>`** folds every fragment,
   plus anything already sitting under `## [Unreleased]`, into a dated version
   section, then deletes the fragments. This runs once, in the release commit,
   where a conflict cannot block anyone.
3. **`--check` validates fragments** and runs in CI and the pre-commit hook: an
   unrecognised section prefix or an entry that is not a bullet fails loudly
   rather than being silently dropped at release.
4. **`CHANGELOG.md` loses its `merge=union` attribute.** With no branch editing
   it, the driver has nothing to resolve, and leaving it would keep implying a
   guarantee that does not hold where it matters.
5. **`docs/adr/README.md` keeps its attribute.** It is generated by
   `scripts/adr-index.mjs` and guarded by a hook, so the resolution for a stale
   index is to regenerate it, not to merge it. Union remains a convenience there
   rather than the mechanism.

## Consequences

Auto-merge becomes reliable. A pull request that adds a fragment cannot be made
stale by an unrelated merge, which is what "armed means finished" was supposed
to mean.

The cost is one indirection: a contributor writes prose in a file whose name
they must choose, and does not see the assembled result until release. The
`--check` hook is what stops that becoming a silent loss.

`git log -p CHANGELOG.md` stops being a per-change history. It becomes a
per-release one, and the per-change history moves to the fragments — which are
in the same commit as the code they describe, so the association is tighter, not
looser.

## Alternatives considered

**Keep `merge=union` and reconcile locally each time.** The status quo. It works
— every one of the five stale pull requests was reconciled in minutes — but it
costs a human round trip per collision and it defeats unattended auto-merge. It
also fails in an actively misleading way: GitHub reports a conflict that does
not exist, so the obvious first move (`gh pr update-branch`) silently does
nothing.

**Generate the changelog from commit messages.** Conventional Commits are
already enforced, so the data exists. Rejected: the entries in this repository
carry reasoning that does not belong in a subject line, and deriving them would
either lose that or move the whole body into the commit. A fragment can be
edited in review; a commit message cannot, without rewriting history.

**Drop the changelog.** Rejected: it is the operator-visible record, and
`docs/releases/` proofs cite it.
