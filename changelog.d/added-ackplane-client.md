- **A repository-side Ackplane client exists, so `federated` coordination resolves (`task:727ae37b4f5a`, ADR-0096).** The new `ackplane-client` crate speaks `ClaimDelegationService` (delegate, renew, release, recover) over the pinned `ackplane-protocol` contract, depending on neither `mindleak-core` nor `lodestar-core` (ADR-0082 clause 1). `ackplane-core` links it only behind the opt-in `federation-client` cargo feature; the standalone build (`mindleak-mcp`, `lodestar-mcp`) stays network- and async-runtime-free by default (ADR-0094 decision 1). The single `FederationUnavailable` refusal is now two distinct, separately-remedied causes — `NoClient` and `ArbiterUnreachable` — so a repository is told what to actually fix. An end-to-end test proves a claim is arbitrated by a real running `ackplane-server` (one owner granted, a second refused by the same compare-and-swap), not just a successful handshake. Routing an actual `task_claim` call through this client remains its own follow-on task; see `gaps.d/no-claim-is-arbitrated-through-ackplane.md`.
