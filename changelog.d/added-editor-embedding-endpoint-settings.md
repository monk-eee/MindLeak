- **Added:** The VS Code extension can now tell both planes where the embedding model lives, via `mindleak.embedUrl` and `mindleak.embedModel`. The extension spawns its own servers and already threaded the database override, the attribution id, the workspace root and every consolidation setting into their environment — but nothing for the embedding endpoint, so a server fell back to the Ollama default and its autonomous index pass could never reach a model hosted anywhere else. Exporting a machine-wide variable does not rescue it: a process inherits its environment once, at launch, so an editor that is already running keeps the old one. Measured before the fix on a machine configured for LM Studio: **121 consecutive `autonomous_index` skips**, every one reporting `nomic-embed-text` unreachable, with 21.4% of the graph holding no vector for the model that was actually configured. Both settings are empty by default, so nothing changes for anyone already on the defaults, and changing either re-launches the servers the same way a path or database override does.
