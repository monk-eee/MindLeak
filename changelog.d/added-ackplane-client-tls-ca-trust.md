- **`register-me`, `ackplane-supervisor`, and `lodestar-mcp`'s federation client can now connect to the documented TLS-enabled Compose topology.** Previously, none of `ackplane-client`'s gRPC clients configured any TLS trust, so connecting to the `ackplane` service exactly as `docker-compose.yml` defines it (TLS on by default, ADR-0132) failed outright — the only workaround was restarting the server in plaintext. A new `MINDLEAK_ACKPLANE_TLS_CA_PATH` env var, when set, trusts that CA certificate in addition to the platform's default roots; unset, behavior is unchanged. `tls-init`'s certificate generation now produces a proper two-tier root CA + signed leaf pair (`/tls/ca.crt` + `/tls/server.crt`) rather than one self-signed certificate wearing both hats — a single self-signed certificate used as its own trust anchor is refused by rustls-webpki (`CaUsedAsEndEntity`) when a client tries to verify it, confirmed empirically before this fix.
