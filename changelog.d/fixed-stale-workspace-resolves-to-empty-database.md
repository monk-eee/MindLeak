- A stale workspace path no longer resolves to a fresh, empty database. When the directory a session was rooted in disappears — most often its own worktree being reclaimed while it is still running — `resolve_database` and `resolve_database_in` now return `RepositoryStorageError::MissingWorkspace` instead of quietly handing back a workspace-local SQLite file with no repository id. Previously this was silent on Linux and macOS (`storage_status` reported `origin: "workspace"` and `repository_id: null`, and `lodestar_stats` reported 0 goals and 0 tasks where it had reported hundreds), because a spawn into a deleted directory reports the same `NotFound` error kind as a missing `git` binary; Windows surfaced an opaque "The directory name is invalid." IO error instead. An explicit database path still wins, and a directory that is simply outside Git still falls back to workspace-local as before.
