### Added

- Added Export, the fourth and last privileged Administration capability ADR-0119 names, closing out the ADR-0105 decision 6 "Backup / export / reset" parity row: a single request-then-receipt flow (unlike Lifecycle purge's two-phase preview/confirm) producing a bounded, redacted representation of the `telemetry_events` data category for a named purpose, gated by its own adopted, tenant-scoped `Export` policy. `POST /api/v1/repositories/:repository_id/administration/exports` refuses (409, no request row created) without an active policy, otherwise queries at most the caller's requested record count, strips every internal identifier (`telemetry_id`/`node_id`/`agent_session_id`), and writes a schema-versioned, unencrypted JSON document (unlike a Snapshot artifact, an export is already bounded and redacted rather than a second copy of production state needing the same custody controls). Idempotent like Snapshot: a replayed request returns the original receipt rather than re-running the query. `GET .../exports/:request_id` reads back the receipt, tenant- and repository-scoped like every other Administration route. Administration's capability list now reports `export` dynamically (unavailable/refused/available) instead of a static refusal.
- Fixed a Windows-only bug in the Snapshot and Export artifact providers: both built their on-disk filename directly from a `namespace:hex` request id, and `:` is invalid in a Windows filename (reserved for drive letters) even though it is fine on Linux and macOS. Snapshot's own integration test never caught this because `pg_dump` is absent on this development machine's PATH, so the write path never actually ran; Export's equivalent test has no such gate and failed immediately, exposing the same bug in both providers. Both now sanitize the request id before building an artifact path.
- Split `crates/ackplane-bridge/src/administration.rs` into a directory module with `policy.rs` (adopted-policy workflow, shared by every privileged operation) and `snapshot.rs` (the platform Snapshot request/receipt flow) as their own files, alongside the existing `purge.rs`/`recovery.rs`/`export.rs` split -- purely a file-layout change with no behavior difference.
