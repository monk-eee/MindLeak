- **The Bridge tenant-scope guard now scans every domain module, not just `main.rs`'s inline routes.** `repository_id_guard.rs`'s structural check (ADR-0098 decision 5) only ever looked at handlers registered directly in `main.rs`; every newer domain merged in as its own sub-router (`administration`, `context`, `delegation`, `design`, `evidence`, `knowledge`, `live_feed`, `supervisor`, `work`, and the shared static assets) was invisible to it, so `every_bridge_route_handler_scopes_its_query_to_the_tenant` passed for roughly half the crate's routes by omission, not by actually checking them. The extraction now also recognizes `post(...)` registrations (main.rs's own `repository_recover_claim` route had the same blind spot) and reads across every router-builder function, filtering out non-handler matches like a store method call or an HTTP header lookup. Every one of the 54 handlers this now covers already carries its tenant scope correctly — this closes a coverage gap in the guard itself, not a live vulnerability.
