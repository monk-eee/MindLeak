- `ackplane-mcp` is the first slice of ADR-0136's MCP front door: a new binary speaking the same newline-delimited JSON-RPC 2.0 MCP protocol as `mindleak-mcp`/`lodestar-mcp`, whose handlers translate into Ackplane's existing typed gRPC services rather than re-implementing any rule locally. It serves one tool so far, `check_enrollment_status`, which carries a freshly signed `NodeEnrollmentService.CheckEnrollmentStatus` request (ADR-0122) and reports the arbiter's verdict unchanged. A repository that has never enrolled is reported as unable to ask rather than as "not enrolled", because no arbiter was consulted. Per ADR-0136 clause 4 this is a local-loopback pilot: any non-loopback `ACKPLANE_MCP_ENDPOINT` is refused, naming the host and the decision it is waiting on, and the process still answers the protocol so that refusal reaches the agent instead of only the log. Nothing about the Local profile changes -- `mindleak-mcp` and `lodestar-mcp` keep their stdio-only, no-network-listener contract, and no core crate is forked onto PostgreSQL.
