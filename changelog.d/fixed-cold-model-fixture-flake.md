- **Fixed:** The cold-model HTTP test fixtures no longer panic when the client under test has already given up. `cold_then_warm_json_endpoint` exists to make a client hit its read timeout and retry, so a socket write that cannot land is an expected outcome of using it — but the harness `expect`ed those writes, so losing the race surfaced as a panic reading `write test model body`. That named the harness's own socket write as the fault, nowhere near the timing race that caused it, and buried the test's real assertion: that the client never received its response. A failed write is now simply not written. The read timeout those fixtures require is also published once as `COLD_CLIENT_READ_TIMEOUT` next to the `COLD_HOLD` it has to sit under, instead of being hard-coded as 100ms independently in both `mindleak-core` and `lodestar-core`; it is raised to 400ms, which widens the window a loaded machine has to serve the retry.
