- **Fixed a Postgres-gated `signing_keys` test collision found while validating an unrelated change.** `revoking_a_key_ends_its_authority_immediately` and `a_second_revocation_is_a_no_op_and_never_moves_revoked_at` both called `test_record` with a fixed literal `public_key_fingerprint`, while `signing_key_id` varied. The table's real unique constraint is on `(tenant_id, repository_id, node_id, public_key_fingerprint, activated_at)` — a tuple that does not include `signing_key_id` — so the two tests collided on that composite key whenever they ran in the same process against the same database, even on a freshly reset volume. `test_record` now derives `public_key_fingerprint` from the caller's already-unique `signing_key_id` instead of a fixed literal.
