- `ackplane-mcp` gains `task_query` (ADR-0139 clause 2), translating a new `WorkQueryService` gRPC service (`ackplane-server`, `ackplane-protocol`, `ackplane-client`) over ADR-0120's read-only Industrial Work projection, exactly as Bridge's first Work read surface (`ackplane-bridge/src/work_api.rs`) already exposes it over HTTP -- no new authority or storage logic. `view` selects the question: `list` (a paged/filterable task list, optionally by `state`, following ADR-0112's pagination discipline), `detail` (requires `task_id`; task, acceptance, event history, and waits), or `doctor` (Board Doctor findings -- missing publication, impossible state/lease combinations, unresolved waits, and declared scope overlap). Every `list` answer carries ADR-0120 decision 6's publication state; `current`/`claims_only`/`not_published` are computed today, matching Bridge's own mapping exactly, while `lagging`/`unavailable` remain uncomputed by either read surface (see `gaps.d/work-publication-state-never-reports-lagging-or-unavailable.md`). Scope discipline matches `active_claims`: an unset `MINDLEAK_ACKPLANE_TENANT_ID`/`MINDLEAK_ACKPLANE_REPOSITORY_ID` is refused by name rather than asked with a blank scope. This tool is materially narrower than Lodestar's own `task_query` (ADR-0139 clause 6): no create, mutation, conformance, or goal/constitution body.
