- **Added:** `lodestar-core` can now route `task_claim` (`claim`/`renew`/`release`/`recover`) through a federated repository's Ackplane claim CAS instead of the local `tasks` table (ADR-0096 clauses 2-4, 6). `Lodestar::with_federated_claim_authority` injects a `FederatedClaimAuthority` implementation; without one (the default), every one of those is exactly today's local CAS, unchanged, and the standalone `lodestar-core`/`lodestar-mcp` dependency closure stays free of `tonic`/`tokio`. A grant is copied into the local task cache — owner, branch, claim window, and declared scope — through new cache-projection store methods; a rejection resolves like a lost local CAS, and a transport failure is a typed `LodestarError::Federated` rather than a silent fall back to local arbitration. `lodestar-mcp` gained the real, network-calling implementation (`federation.rs`, built only behind the existing `federation-client` cargo feature): it resolves this repository's federated claim identity (endpoint, tenant, repository, node, signing key) from explicit environment variables, signs every request with a new `ackplane-client::authenticate` helper reusing the exact domain-separated signing-bytes contract `ackplane-server` verifies against (now shared through `ackplane-protocol::claim_auth` so client and server can never drift), and bridges each synchronous call with a fresh current-thread runtime, mirroring `compiled_federation_readiness`'s existing pattern. Proven end-to-end against a real `ackplane-server` and Postgres, reusing `ackplane-client`'s existing arbitration fixture pattern rather than a second protocol harness. The federated recovery path covers only an expired lease — the wire contract has no reviewer field yet, so a paused-task transfer naming a human reviewer is refused rather than silently attempted without one. `gaps.d/no-claim-is-arbitrated-through-ackplane.md` is narrowed to what remains outside the wire contract (park/answer); the node signing key's interim environment-variable sourcing is tracked in a new `gaps.d/the-node-signing-key-has-no-credential-facility-yet.md`, pending the OS-credential-facility storage ADR-0085 decision 2 describes.
