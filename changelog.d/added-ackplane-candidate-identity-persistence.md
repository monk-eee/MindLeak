- **A repository's candidate Ackplane identity now persists between processes.** `ackplane_client::identity` sources and reloads the `node_id` / `key_fingerprint` / signing key `register-me request`/`activate` already write to disk, and builds a freshly signed `CheckEnrollmentStatus` request from it. `register-me`'s `--key-path` now defaults to the same repository-local path (`.mindleak/ackplane-node.key`, override with `MINDLEAK_ACKPLANE_KEY_PATH`) on every subcommand, so `request` and `activate` agree without a human passing a path between them. Narrows `gaps.d/ackplane-client-cannot-detect-unenrolled-repositories.md`: wiring this into a local plane's own startup readiness check remains deliberately out of scope, since that would mean `lodestar-mcp`/`mindleak-mcp` loading and signing with the raw private key directly, which ADR-0100 decision 3 reserves for the not-yet-built `ackplane-node` companion's non-exporting signer.
