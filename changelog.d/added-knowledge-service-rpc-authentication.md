- **Added:** `KnowledgeService`'s three mutating RPCs (`RecordKnowledge`, `RecallKnowledge`, `RetireKnowledge`) now require a signed `KnowledgeAuthentication` naming the enrolled node making the request (ADR-0108). It mirrors `ClaimDelegationService`'s operation-signing scheme (ADR-0100 decision 10) but with its own domain separator (`knowledge_auth::KNOWLEDGE_DOMAIN`), its own `KnowledgeOperation` enum binding each RPC's operation-specific fields into the signed bytes, and its own `knowledge_authentication_nonces` replay table -- not shared with claims', so a captured nonce in one domain can never pre-empt a legitimate request in the other. Verification resolves the signing key through the existing `signing_keys` registry (no new key registry, no dependency on the not-yet-built `ackplane-node` companion) and refuses an absent, unresolvable, stale, replayed, or wrong-operation signature before the request ever reaches the knowledge store. This closes `gaps.d/ackplane-knowledge-service-rpcs-are-unauthenticated.md`.
