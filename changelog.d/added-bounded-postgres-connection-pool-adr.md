- ADR-0143 is accepted: Postgres access moves from one dedicated, lifetime-held connection per store (23 store types across `ackplane-server`/`ackplane-bridge` repeat this shape) to a single bounded `deadpool-postgres` pool per process, one checked-out connection per call or per held transaction. This closes the actual unbounded demand behind `gaps.d/the-postgres-connection-ceiling-fails-the-suite-misleadingly.md`: a running service process already holds a small, deterministic number of connections, but `cargo test --all` opens one raw connection per store per test with no shared cap, which is what exhausted Postgres's connection ceiling even after it was raised. The ADR is explicit that a held transaction (the `delegation_store::authorization` lock-contention test depends on this) keeps one checked-out connection for its whole duration, never releases it mid-transaction, and that migration proceeds store-by-store as a sequence of individually complete commits rather than one sprawling rewrite. Design-only: no code ships with this ADR.
