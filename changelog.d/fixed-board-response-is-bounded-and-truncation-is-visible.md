- **`task_query(view="board")` now bounds its own response and says so.** `board()` (`crates/lodestar-mcp/src/tools/executive/tasks.rs`) still returned every task the ledger had ever held as one unbounded `Vec<Task>` even after `detail=false` (previous fix) removed the three per-row engine lookups — measured at ~403 KB on this repository's own board (1,019 tasks) with `detail=false` alone, the same unbounded-payload shape `active_knowledge` had before it was capped. `board()` now answers `{count, tasks, tasks_truncated}`: `count` is the true total (computed before truncation), `tasks` is capped to the 200 most recently touched (`bounded_by_recency`, the same helper `existing_work` already uses), and `tasks_truncated` says whether anything was dropped. A new `limit` argument on `task_query` (default 200, `limit: 0` disables the cap entirely) lets a caller that genuinely needs full history opt out explicitly rather than silently losing rows it depends on.
  Every consumer of the old bare-array shape was migrated to read `.tasks` (or is unaffected because it already defensively unwrapped both shapes): `scripts/canonical-push.mjs`'s claim gate, `scripts/status.mjs`, `scripts/stranded-report.mjs`, and `scripts/evaluate-pr-effectiveness.mjs` all pass `limit: 0` since each needs to see every non-terminal (or, for the last two, every) task, not just the 200 most recently touched; `scripts/board-health.mjs` does the same for its full-board health report. `editors/vscode/src/util.ts` gained a shared `boardTasks()` unwrap helper, used by `extension.ts`'s `refreshBoard`/`refreshEvidence` and `fleetController.ts`'s Fleet pane read — these UI views keep the default 200-task cap, which is the fix for the original problem (an oversized `task_query` result inflating VS Code's own persisted chat-session state). `clients/node/mindleak-client`'s `TaskService.board()` SDK method unwraps either response shape internally so its own return type (`Promise<LodestarTask[]>`) never changes for callers, and now accepts an optional `limit` passthrough. `scripts/worktree-reclaim.mjs` needed no change: it already read `Array.isArray(response) ? response : response?.tasks`.
