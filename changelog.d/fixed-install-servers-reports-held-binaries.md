- `install-servers` now says when a replaced server is still running. A superseded binary that cannot be deleted is a process still holding it, which is the only portable evidence that the old code is still being served; `pruneSupersededInstalls` discarded that in a bare `catch` and now returns `{ pruned, held }`. Both the install and `--prune` paths report that any held binary means those servers are still running the code the install replaced, so the change is not live until they restart. Windows only, since Unix unlinks a running binary without leaving residue.
