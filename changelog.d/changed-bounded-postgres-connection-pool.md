- **Ackplane processes now open one bounded PostgreSQL pool instead of one dedicated connection per store.** `ACKPLANE_DB_POOL_MAX_SIZE` (default 16 for a service, 8 for a test process) caps how many connections a single process can hold no matter how many stores or tasks it starts, and `ACKPLANE_DB_POOL_TIMEOUT_MS` (default 5000) bounds the wait for one, so exhaustion is a typed refusal naming the pool rather than a request that hangs. Both settings refuse a malformed or zero value rather than silently falling back to the default. This is the first slice of ADR-0143: the pool exists and `LiveFeedStore` is migrated onto it; every other store keeps its current dedicated connection until its own turn, and none is left half-migrated.
