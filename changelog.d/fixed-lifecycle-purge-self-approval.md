### Fixed

- **Lifecycle purge no longer lets the same principal both request and confirm its own purge.** `confirm_lifecycle_purge`'s only identity check was that the confirming caller was the same tenant/principal that submitted the preview -- the opposite of ADR-0119 decision 7's requirement ("an agent or model cannot approve its own purge"). A confirm call now requires a `confirming_label` distinct from the request's `requested_by` principal, the same same-string self-review guard `resolve_task` already applies (ADR-0071) -- attributed, not authenticated, since this deployment has no separate identity provider. Because `administration_purge_receipts` allows only one receipt per request ever, a same-label or empty-label attempt is refused as a plain validation error (`400`) that writes no receipt, so a caller can retry with a correct label inside the same confirmation window; the validated label is retained on the one receipt a request ever gets (never on an `expired` receipt, since nothing was validly confirmed in time).
