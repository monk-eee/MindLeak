- ADR-0147 is accepted: `task_claim` gains an optional caller-declared `branch_committed_paths` (the branch's existing diff since base, computed by the caller the same way `canonical-push.mjs` already computes its own `changed` variable, just earlier), and `governing_clauses_for_task` reports governing clauses for those paths in a new `branch_inherited` field, kept separate from the task's own declared scope. This resolves `gaps.d/consecutive-tasks-on-one-branch-inherit-governed-scope.md`'s open design question: measured twice, a task claimed on a long-lived branch inherits every prior task's already-committed files as its own evidence (not only across a reconciliation merge — any unmerged prior work on the branch), and earns `drift` for files it never touched. The already-working exit (`also_serves` declared before the finding) now has something to declare against at claim time instead of only after completion. Evidence semantics (`changed_node_ids`, ADR-0009) are explicitly unchanged: this ADR only adds claim-time visibility, never a gate, and never narrows what evidence counts as. Design-only: no code ships with this ADR.
