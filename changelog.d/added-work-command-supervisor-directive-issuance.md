### Added

- Added Assign/Steer/Pause/Resume/Drain to Industrial Work commands (ADR-0125 decision 7): a confirmed supervisor-directed command now issues a matching ADR-0107 directive to the enrolled supervisor session its payload names, atomically with the command's own receipt (`WorkCommandStore::execute_confirmed` and `directive_store::enqueue_in_transaction` now share one transaction rather than a second connection). The immediate receipt is `pending_delivery` or `refused` (missing capability, unknown session, or a node mismatch) -- never a claim that the worker already paused, resumed, or accepted an assignment. Only the addressed supervisor's own later `applied`/`refused`/`failed`/`expired` directive receipt (`WorkCommandStore::apply_directive_receipt`) appends the corresponding `work_task_history` event and, for `applied`, changes the task's projected state (Pause/Resume/Drain move it; Assign/Steer record the attempt). `accepted` never does. Migration `0053_work_command_directives.sql` adds the `work_commands.directive_id` link and widens `work_task_history`'s event-kind range to cover the five new kinds. Wiring this into the live NodeSync ingestion path, and any Bridge route, remains a later slice -- this one is store-level only, following the same pattern the three prior Work-command slices already established.
