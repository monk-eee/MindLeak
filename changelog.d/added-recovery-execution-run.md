### Added

- Added production recovery execution (ADR-0145 slice 4), the capability the ADR names but slices 1-3 only prepared for: `AdministrationStore::execute_recovery` consumes a previously previewed and confirmed recovery-execution request and runs a real `pg_restore --clean --if-exists --no-owner` against the authoritative `ACKPLANE_DATABASE_URL` (`snapshot_provider::execute_recovery`), unlike rehearsal's restore into a freshly created, empty scratch database, production's target already holds live objects the restore must overwrite. Re-checks, at the moment it runs rather than only at preview time, that the deployment is attested single-tenant (decision 6) and that a rehearsal of the exact artifact digest passed inside a 24-hour freshness window (`MAX_REHEARSAL_FRESHNESS`, decision 3); either refusal is a durable `Refused` `RecoveryExecutionReceipt`, never a bare error, and a genuine `pg_restore` failure is an honest `Failed` receipt, never silently retried with checks relaxed or papered over by falling back to the pre-restore safety Snapshot (decision 8). New Bridge route `POST /api/v1/administration/recovery-executions/:request_id/execute` needs no signature of its own — the preview/confirm pair is already decision 4's complete dual-signing-key authorization — and is idempotent: replaying against an already-decided request returns the same receipt without ever running `pg_restore` twice. New append-only `administration_recovery_execution_receipts` table (migration key 62).
