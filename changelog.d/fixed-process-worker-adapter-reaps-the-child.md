- **`ProcessWorkerAdapter::terminate` now reaps the worker it kills instead of leaving a zombie on Unix.** `Child::kill` only sends the signal, and `std::process::Child`'s `Drop` does not reap either, so a long-lived supervisor that force-terminated many short-lived workers accumulated one zombie entry in the OS process table per termination. `terminate` now waits for the killed child. The already-exited path was never affected: `try_wait` reaps on success. Guarded by a regression test that reads the process table directly rather than asserting `terminate` returned `Ok` -- the un-reaped case returns `Ok` too, so only the process table distinguishes the fix from the bug. That assertion is Linux-only because it reads `/proc`; the fix itself is Unix-wide, and Windows never had the exposure since a `Child`'s process handle is closed on drop regardless.
