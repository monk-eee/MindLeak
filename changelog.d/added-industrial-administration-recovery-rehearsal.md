### Added

- Added Recovery rehearsal (ADR-0145 slice 1), the real restore drill ADR-0119 decision 6 always assumed but this repository never built: `snapshot_provider::rehearse_recovery` decrypts a Snapshot artifact exactly like inspection does, then actually restores it into an isolated, ephemeral scratch database — provisioned on a required, separately configured `ACKPLANE_REHEARSAL_DATABASE_URL`, never `ACKPLANE_DATABASE_URL` — runs this deployment's exact migration sequence against it (the same store list `bin/migrate.rs` runs at boot, now shared via the new `ackplane_server::schema_migration` module rather than forked), and reconciles the restored table count against the archive's own table of contents. A misconfigured rehearsal url that names the same host/port/database as the authoritative one is refused outright, not warned about. Durably recorded, append-only, in a new `administration_recovery_rehearsals` table (migration key 57) — two rehearsals of the same artifact are legitimately distinct events, not replays, mirroring Recovery inspection's own reasoning. No Bridge HTTP route or execution path yet; those are later slices of the same ADR.
